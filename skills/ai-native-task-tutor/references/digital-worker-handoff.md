# Digital Worker Implementation Handoff

Use this reference only after the task has been understood and an implementation plan has been agreed locally. The Digital Worker implements; it does not teach, calibrate to the learner, update mastery, or participate in learning checkpoints.

Translate the agreed plan into the normal format accepted by the company's Digital Worker. Include only what improves implementation correctness:

```markdown
# Goal
[Observable behavior to implement]

# Current behavior
[Concise repository-grounded summary]

# Desired behavior and acceptance criteria
- [Behavioral criterion]
- [Compatibility or failure criterion]
- [Normal validation criterion]

# Implementation plan
1. [Concrete change]
2. [Concrete change]
3. [Concrete change]

# Scope and constraints
- Repositories/directories allowed: [...]
- Existing behavior that must remain unchanged: [...]
- Team conventions and compatibility constraints: [...]
- Actions that are out of scope or require separate authorization: [...]

# Validation
- [Expected build/test/check commands supported by the repository]
```

Do not add tutoring requests, quizzes, learning reports, mastery evaluation, or learner-specific instructions. Do not rely on the worker to provide an educational explanation.

After completion, pull the actual changes locally. Treat the code, diff, tests, and local runtime behavior—not a generated summary—as the material to inspect and learn from with Windsurf or Copilot.
